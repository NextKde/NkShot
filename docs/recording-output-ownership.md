# Recording output ownership (077)

077 replaces the conservative **private-output** cancellation limitation in 076
with an explicit reservation and identity check. The final 077 build passed the checks below; earlier 076 results alone did not
prove these new paths.

## Application-private output

`OwnedRecordingOutput` reserves the existing relative filename inside the private
temporary root. It does not insert a per-attempt directory or change the filename
prefix used by saving/export. The root must belong to the current user and grant
no group/other permissions. Directory traversal uses held directory descriptors,
`openat` with `O_NOFOLLOW`, and owner-only `mkdirat` for missing components.
Empty, dot and parent components are rejected. The final file is exclusively
created with mode 0600, without following a symlink; an existing file is refused.
The helper holds both the file and its parent directory descriptors.

Before recorder start, `identityMatches()` revalidates the root/parent chain and
the leaf against the held file. It requires an owner-only regular file, a single
link, and matching device/inode. Directory relocation, symlink/file replacement,
hard links or broadened permissions invalidate that check.

Cleanup is explicit, not an unconditional destructor action:

- Cancellation before producer start can clean the reservation immediately.
- Cancellation while Starting retains the reservation/source until explicit
  recorder Idle, then requests cleanup.
- Success releases descriptors and retains the completed file.
- Failure after entering Recording preserves the output for recovery.
- During adapter destruction, pending cancellation cleanup must follow producer
  stop/thread completion. Destroying the helper itself only releases descriptors.

The native KPipeWire sequence opens AVIO for writing, then writes any trailer and
closes AVIO before producer completion/Idle. Tests must confirm that writing into
the reserved path keeps its inode and that cleanup does not race a live producer.

Cleanup compares the live directory chain plus held-file and directory-entry
identity before `unlinkat`. It never recursively removes directories or unknown
siblings. A missing file is not an error. Identity/permissions changes are
preserved, with an asynchronous warning rather than failure of a newer recording
attempt. A cleanup failure also reports a warning. The dedicated
`temporaryOutputCleanupWarning` channel must not cancel or re-label a subsequent
attempt.

**Concurrency limit:** POSIX has no atomic “unlink this pathname only if it still
names this inode” operation. Owner-only directories exclude other users, not a
malicious process running as the same UID. A same-UID swap between the final
check and pathname use/unlink remains a TOCTOU limitation. These checks do not
claim an atomic security boundary against such a process.

## Explicit output paths

Explicit outputs use a different policy. Existing files are rejected with a
request to choose a new filename. A new explicit file is reserved with NewOnly,
and its descriptor identity is checked against the path immediately before
start. It is **never automatically deleted** by recording cancellation or failure.
Cancellation may therefore leave an empty or partial explicit output. This
preservation rule avoids treating a user-selected pathname as disposable private
storage. It also means callers should choose a fresh filename for retry.

## Verification

The final build passed 21/21 CTest targets, 18/18 static checks and whitespace.
Detailed evidence:

- 16 QtTest results, zero skips, from real filesystem helper tests: bytes written then removed; release/destruction
  preserve; existing/symlink/hard-link refusal; leaf and parent replacement,
  parent relocation, directory replacement, unknown sibling preservation;
  strict relative components, special-character filenames, bad roots, expanded
  permissions, repeated cleanup and reserve reuse.
- Actual FFmpeg CLI output into a reservation, verifying the inode is retained.
  A missing CLI is an explicit skip of this compatibility check, not success.
- 17 real-adapter scenario groups with injected providers: private cancellation before start,
  outstanding-start cancellation after Idle, success release, preservation after
  actual Recording, explicit-path behavior, warning delivery and stale-attempt
  isolation. Native patched KPipeWire failure paths are distinct from fake media.
- Five actual Core/QML cancellation/restoration scenarios and three warning UI
  scenarios (light/dark/420×520), individually reviewed as real software-window
  captures. The warning is generated by actual synthetic-file cleanup refusal
  and handed through the test-only bridge to the real Core warning signal.
- Independent validation: 13 QtTest results, including direct libavformat
  `avio_open`/write/flush/close, retained inode identity, root rename/permissions,
  FIFO replacement, hard links, NUL paths and 200-iteration descriptor stability;
  17 existing workbench flows and 18 external Gio portal/QML scenarios passed.

No real KDE/PipeWire capture, GPU encoding, audible audio, A/V synchronization or
native recorded-media acceptance is established by these ownership checks.

## Native producer source basis

The pinned [KPipeWire recorder implementation](https://github.com/KDE/kpipewire/blob/f30b39c53092673d136660c8deaf24d3935723eb/src/pipewirerecord.cpp)
deduces the muxer from the output filename and opens it with `avio_open` in write
mode. `PipeWireRecordProduce::cleanup()` writes the trailer, closes AVIO and frees
the format context. Producer destruction drains/stops work before cleanup and
emits `finished` afterward; the encoded-stream adapter then reports Idle. Its
destructor calls stop and waits for the producer thread. This is the basis for
post-Idle or post-recorder-destruction cleanup, not an inference that the UI's
Starting phase means no writer exists. The controlled QFile producer tests retain
the write handle after Cancel, append and flush a real tail, then close before
Idle; these are not represented as native AVIO or desktop recording.
